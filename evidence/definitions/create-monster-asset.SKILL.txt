# 해양 괴수 컨셉부터 정적 모델까지

함선과 다른 해부 구조·부속지·자세를 가진 해양 괴수를 제작한다. 함선용 컨셉·멀티뷰 스킬로 괴수를 생성하지 않는다. 기본은 고래·크라켄·거대오징어이며 적대 변형·사람·배경·리깅·애니메이션은 자동 추가하지 않는다.

## 담당과 입력

- [작업영역 계약](../../../_workspace/AGENTS.md)과 [공통 계약](../../../_workspace/shared/agent-workflow.md)을 따른다. **`monster-concept-artist`**가 자기 `monsters/<asset_id>/concept/`와 `multiview/`에서 디자인·자기 검수를 담당한다. 메인은 `coordinator/monsters/<asset_id>/`에서 pipeline·모델·보정을 관리한다. 디렉터는 자기 영역 또는 메시지로 판단을 반환한다.
- 시작 시 실제 괴수 역할 호출 가능 여부를 확인한다. 새 TOML 파일이 있다는 사실만으로 역할 로딩·호출 성공을 주장하지 않는다. 역할을 사용할 수 없으면 필요한 로딩/새 세션을 안내하고 입력 정리만 진행한다. 다른 아티스트나 메인 직접 디자인으로 우회하지 않는다.
- `asset_id`, 허용 영역의 실제 `subject_reference`, 등록 `style_reference`, 요청 종료 단계, 모델 호출 권한·비용 상한을 고정한다. 선택한 승인 컨셉/멀티뷰로 시작하면 버전·해시를 대신 입력으로 고정하고 새 원본 컨셉을 강요하지 않는다.
- [20종 원본 안내](../create-unit-assets/references/catalog.md)에 따라 괴수 아틀라스를 분리해 사용한다. 각 개체와 스타일 이미지를 실제로 확인한다. 원본 경로나 PDF 썸네일만 전달한 것을 실제 이미지 전달로 기록하지 않는다.
- 메인은 제작자가 게시한 shared 사본을 사용하고 제작자의 전용 폴더에 접근하지 않는다. 제작자는 모델 API·Godot 패키징을 실행하지 않는다.

## 제작과 연결

1. 실제 `art-director`와 입력, 보존 실루엣, 몸통 비례, 부속지 수/접합, 고정 자세, 전방·수면 기준을 협의한다. 원본에서 보이지 않는 구조는 추정으로 명시한다.
2. [괴수 컨셉·멀티뷰 계약](references/concept-multiview.md)에 따라 괴수 아티스트가 3/4 한 장을 제작하고 자기 검수 직후 독립 디렉터 검수를 받는다. 수정 요구는 다음 미사용 버전으로 반영한다.
3. 컨셉까지만 요청하면 승인 후보와 기록을 전달하고 종료한다. 멀티뷰까지 요청했다면 승인된 같은 컨셉을 고정해 네 독립 방향과 전체 세트를 검수한다. 기준 컨셉 없이 네 방향에서 각각 새 디자인을 만들지 않는다.
4. 모델링까지 요청받고 세트 승인 근거가 있으면 메인에게 네 파일과 해시·프롬프트·판정의 shared 사본을 인계한다. [공통 모델 생성·보정 계약](../create-ship-asset/references/model-stage.md)을 `asset_kind=sea_creature`에 적용한다. 함선 구조 검수 항목을 괴수에게 적용하지 않는다.
5. 메인은 최종 GLB의 실제 6방향 렌더와 검사 결과를 디렉터에게 검수받는다. 몸통·팔/촉수/지느러미 접합, 부속지 소실·융합·떠 있는 조각, 과도한 관통, 좌우/전후 혼동, 원본 실루엣 변형을 우선 확인한다. 정적 메시 검수를 리깅·관절 변형 품질 보증으로 표현하지 않는다.
6. 정적 모델 승인까지가 단독 모델 요청의 종료점이다. 게임용 패키지 요청 또는 총괄의 `end_stage=package`가 있으면 같은 pipeline과 사용량을 유지해 [create-unit-assets 납품 단계](../create-unit-assets/references/delivery.md)로 연결한다. 총괄의 처음부터 다시 시작하지 않는다.

## 기록·한도·완료

- 메인의 `monsters/<asset_id>/pipeline.json`과 제작자의 manifest를 shared 인계로 연결한다. 종류는 `sea_creature`다. [배치·재개 계약](../create-unit-assets/references/batch-state.md)의 승인·입력 변경·비용·응답 유실 규칙을 단독 실행에도 적용하며 단독이면 자산 하나의 기록으로 관리한다.
- 기본 컨셉 3개, 멀티뷰 최초+수정 2회/총 12장, 모델 최초+수정 2회/유료 호출 최대 3건이다. 실패 호출·국소 보정·이전 실행 사용량도 해당 단계 기록에 남긴다. 같은 결함의 수정 두 번 실패 또는 한도 소진이면 종료한다.
- 실제 디렉터의 대상 해시 연결 승인과 요청 단계의 실제 파일이 있어야 완료다. `changes_requested`, `blocked_missing_evidence`, 사용자 선택, 반복/한도 종료를 구분한다. 폴더명·자기 검수·서비스 성공으로 승인하지 않는다.
- 완료 시 원본/선택 버전, 대표 미리보기·모델 경로, 판정·남은 결함, 실제/미확정 비용과 다음 호출을 간결히 전달한다.

## 호출 예시

- `$create-monster-asset 허용 inbox의 kraken 원본과 공통 스타일로 컨셉 한 장을 만들어줘.`
- `$create-monster-asset squid의 승인 concept v002로 멀티뷰까지만 만들어줘.`
- `$create-monster-asset whale의 승인 멀티뷰에서 정적 모델까지 재개해줘. 전체 비용 상한은 100크레딧.`

예시 금액은 견적이 아니다. 실제 요금·입력·사용자 한도에 따라 제출 여부를 판단한다.
