# 함선 멀티뷰 제작

같은 3/4 시안을 네 방향 생성 모두의 고정 기준으로 사용한다. 결과는 모델링용 래스터 참조이며 기하학적으로 정확한 정사영이나 실제 메시가 아니다. 프롬프트·브리프·검수 기록은 한국어로 작성한다.

## 담당과 접근

- 담당은 `character-concept-artist`다. 메인이 직접 실행하면 자기 작업폴더를 사용한다. [접근 규칙](../../../_workspace/AGENTS.md)과 [공통 계약](../../../_workspace/shared/agent-workflow.md)을 따른다. 작업 데이터는 호출자의 전용 영역과 shared의 실제 사본만 사용한다. 검수 사본은 `shared/review-inputs/<handoff_id>/<publisher_role>/`의 자기 영역에 기본 게시할 수 있으며 그 밖의 shared는 읽기 전용이다.
- `imagegen`은 이 제작 회차 안의 도구 단계다. 시작 협의와 독립 검수는 `art-director`에게 실제 위임하며 내부 도구마다 중복 위임하지 않는다.
- 외부 생성 파일과 다른 역할 폴더를 직접 열거나 복사하지 않는다. 호스트가 전달한 실제 이미지 컨텍스트 또는 허용 영역의 사본으로 작업한다. 외부 저장만 가능한 경우 반입이 필요함을 알리고 로컬 저장은 미완료로 기록한다. 저장 경로 제한을 이유로 API로 전환하지 않는다.

## 기준 시안과 브리프

1. 실제 `concept_reference` 한 장과 `asset_id`, 컨셉 버전·해시를 확인한다. 파일명이나 수정 시각만으로 사용자 선택을 추정하지 않는다. 사용자가 최근 시안을 지정했고 허용 기록에 대상이 명확하면 재질문하지 않는다.
2. 네 방향 모두 이 컨셉의 구조·색·재질·스타일을 유지한다. 원래 디자인·스타일 참조가 있으면 출처와 보조 검증 자료로 기록하되, 멀티뷰 단계에서 선택한 컨셉을 다시 디자인하지 않는다. 별도 스타일 이미지가 없다는 이유로 유효한 컨셉 기반 작업을 막지 않는다.
3. 새 3/4 시안부터 요청받았다면 `create-character-concept`로 제작·독립 검수한 뒤 이 단계로 연결한다. 사용자가 새 컨셉부터 네 방향까지 요청한 경우 디렉터 승인 후보를 이번 파생 작업의 기준으로 삼을 수 있다. 사용자 최종 선택 상태는 별도로 보존한다. 컨셉만 요청받았다면 멀티뷰를 자동 실행하지 않는다.
4. 보존할 실루엣·선체 비례·갑판 층수·돛·무장·장식의 수와 위치를 정리한다. 관찰 사실, 가려진 면의 추정, 사용자 지정 사항을 분리한다. 좌우 반전을 비대칭 반대편 구조 설계로 대체하지 않는다.
5. 생성 전에 디렉터와 실제 기준 이미지, 방향별 구성, 추정 구조, 배율·기준선·배경·조명 및 검수 기준을 협의한다. 구조가 읽히지 않아 설계 선택이 필요한 부분만 확인한다.

## 방향과 생성

| 파일 역할 | 바라보는 면 | 화면 방향 |
| --- | --- | --- |
| `front` | 선수 정면 | 선수 중심에서 선미 쪽을 봄 |
| `left` | 좌현 측면 | 선수는 화면 왼쪽 |
| `right` | 우현 측면 | 선수는 화면 오른쪽 |
| `back` | 선미 정면 | 선미 중심에서 선수 쪽을 봄 |

인계 축은 +Y 위, -Z 선수, -X 좌현, +X 우현이다. 실제 3D 모델의 축을 검증한 것으로 표시하지 않는다.

방향 계약은 `local-sides-v2`다. +Y 위의 비반전 카메라에서 Left는 -X 쪽을 관찰하고 선수(-Z)가 화면 왼쪽, Right는 +X 쪽을 관찰하고 선수가 화면 오른쪽이다. 과거 기록에는 화면 방향 설명이 반대인 관례가 있으므로 기존 파일·판정은 보존한다. 재개 시 실제 구조와 보이는 면으로 `source_label`, `observed_side`, `canonical_direction` 대응을 기록하고 새 입력 매핑에 디렉터 세트 검수를 받는다. 해시 불변 파일은 재사용할 수 있지만 파일명만 바꾸거나 이미지를 좌우 반전해 새 기준 승인으로 간주하지 않는다. 면을 판별할 근거가 없으면 `blocked_missing_evidence`로 둔다.


- 방향별 한 번의 내장 이미지 도구 호출로 함선 한 척 전체를 담은 독립 이미지 한 장을 만든다. 기본 순서는 Front, Left, Right, Back이다. 콜라주나 네 칸짜리 보드를 최종 산출물로 대신하지 않는다.
- 매 호출에 고정한 `concept_reference` 실제 이미지를 포함한다. 이미 검수한 방향은 `consistency_reference`, 수정할 이전 결과는 `previous_result`로 구분하며 원래 3/4 기준을 대체하지 않는다. 로컬 입력은 먼저 실제로 열어 확인한다.
- 수평 정면·측면·후면과 원근 왜곡이 적은 정사영풍을 요청한다. 3/4 카메라를 반복하지 않는다. 공통 캔버스·축척·수직 기준선과 여백을 브리프에 정하고, 정면의 폭과 측면의 길이를 각각 화면 가득 채우려고 방향별 확대율을 바꾸지 않는다.
- 중립 단색 배경, 일관된 조명과 약한 접지 그림자, 잘리지 않은 노·돛대·선수·선미를 유지한다. 사람·물·풍경·문자·라벨·UI는 추가하지 않는다. 실제 출력 형식과 크기는 확인한 값만 기록한다.
- 프롬프트에는 입력별 역할, 대상 방향, 유지할 구조·스타일, 가려진 구조의 합의, 수정 항목을 명시한다. `imagegen` 스킬의 현재 내장 도구 지침을 따른다. 선호 이미지 모델과 실제 도구 보고 모델을 구분하며 보고되지 않은 모델·seed는 `unknown`으로 둔다.

## 검수와 수정 예산

각 방향 생성과 자기 검수 직후 디렉터를 자동 호출한다. 실제 기준·후보 이미지, 방향, 세트 버전, 해시, 실제 프롬프트, 자기 검수와 직전 피드백을 전달한다. 디렉터는 원본 보존·방향·비례·구조·스타일·완전한 실루엣을 검수한다. 네 장이 모이면 동일한 기준으로 교차 검수하여 구성품 수·위치·높이와 좌우 비대칭을 확인한다. 개별 방향 판정은 세트 승인으로 승격하지 않는다.

- 기본 예산은 최초 세트 1회와 수정 회차 최대 2회다. 각 회차에서 각 방향은 최대 1개 새 후보만 만든다. 최대 생성량은 총 12장이며 실패한 생성 호출도 실행 기록에 남기고 자동 추가 재시도하지 않는다. 사용자 지정 예산이 우선한다.
- 한 방향만 수정해도 수정 회차 1회를 소비한다. 한 회차에서 같은 방향을 다시 고치지 않는다. 최초 회차의 개별 검수에서 발견한 수정은 다음 회차로 모으고, 근거가 충분하면 나머지 방향 제작과 세트 검수를 진행한다.
- `changes_requested`면 필수 수정만 다음 미사용 세트 버전으로 제작한다. 영향 없는 방향은 재사용하고 출처 버전·해시를 기록한다. 다음 회차 전 수정 대상을 모아 확정하며, 수정 후에는 바뀐 이미지와 재사용한 이미지를 포함한 전체 세트를 다시 검수한다.
- 최종 세트가 `approved_for_next_stage`면 종료한다. 선택 취향만으로 추가 생성하지 않는다. 사용자 최종 승인과 모델 적용 상태는 별도다.
- `blocked_missing_evidence`면 같은 후보의 실제 자료 전달부터 보완한다. 근거 부족을 해결하기 위해 새 이미지를 생성하지 않는다. 해시와 이미지의 연결이 불명확한 판정은 예비 피드백이며 정식 승인으로 기록하지 않는다.
- 수정 2회 뒤에도 같은 필수 결함이 남으면 `repeated_issue`, 그 외 예산 소진은 `iteration_limit_reached`로 종료한다. 미승인 세트를 승인으로 바꾸거나 방향별 별도 회차를 시작해 한도를 늘리지 않는다.

## 기록과 전달

결과는 `작업폴더/ships/<asset_id>/multiview/vNNN/`에 저장한다. 컨셉 버전과 멀티뷰 버전은 독립적으로 증가하며 기존 산출물을 덮어쓰지 않는다. 방향별 실제 형식의 이미지 네 장, `prompts.md`, `review.md`, `manifest.json`을 둔다.

세트 manifest에는 고정 컨셉의 ID·버전·허용 경로·해시, 방향별 파일·해시·크기·생성 회차·재사용 출처, 실제 입력 순서와 프롬프트 위치, 생성/로컬 반입 상태, 방향별 검수와 세트 검수, 실행 종료 사유, 사용자 선택 상태를 기록한다. 자산 루트 manifest의 기존 컨셉·모델 이력과 스키마를 보존하며 멀티뷰 항목만 추가한다.

실제 디렉터 식별자·응답·수정 요청·채택 여부·수정 결과를 기록한다. 인계는 자기 outbox와 기본 shared 검수 게시를 사용하며 상대 inbox에 직접 쓰지 않는다. 디렉터는 게시된 실제 이미지와 해시를 확인한다. 이미지 컨텍스트 전달이 실패해도 게시 허용을 다시 묻지 않는다. 완료 시 기준 3/4 버전, 네 이미지, 실제 저장 여부와 경로, 세트 판정, 남은 추정을 전달한다. Tripo 업로드·메시 생성·Godot 통합은 실행하지 않는다.
