# 작업 영역 접근 계약

이 문서의 역할별 접근·반입 제한은 아트 제작·검수·인계에 적용한다. 사용자 요청에 따른 일반 개발 작업은 루트 AGENTS.md의 일반 개발 작업 접근 규칙을 우선한다. 게임 소스·런타임 자산·설정·문서·테스트 원본의 직접 읽기·수정·검증, 저장소 도구 실행과 프로젝트 캐시 생성을 허용하며 사본 반입과 회차별 재승인은 요구하지 않는다. 다른 역할의 전용 폴더와 보존 아트 자료에는 이 예외를 적용하지 않는다.

`_workspace`는 저장소 루트 바로 아래의 이 폴더 하나를 뜻한다. 다른 위치의 같은 이름 폴더는 허용 대상이 아니다. 지침 로딩·명시적인 설정 유지보수 예외는 루트 AGENTS.md를 따른다.

| 실행 주체 | 읽기·쓰기 가능한 전용 영역 | 추가 공유 영역 |
| --- | --- | --- |
| 메인 에이전트 | `coordinator/` | `shared/` |
| `character-concept-artist` | `character-concept-artist/` | `shared/` |
| `monster-concept-artist` | `monster-concept-artist/` | `shared/` |
| `environment-concept-artist` | `environment-concept-artist/` | `shared/` |
| `portrait-artist` | `portrait-artist/` | `shared/` |
| `art-director` | `art-director/` | `shared/` |
| 모든 스킬·도구·스크립트 | 호출자의 전용 영역 | `shared/` |

`shared/`는 모두 읽을 수 있으며 검수 사본은 아래 기본 게시 규칙에 따라 작성할 수 있다.

표의 경로는 이 폴더 기준이다. 등록되지 않은 하위 에이전트는 전용 영역을 명시적으로 배정받기 전 파일 작업을 시작하지 않는다. 메인 에이전트가 아티스트 스킬을 직접 실행해도 `coordinator/`를 사용하며 역할 폴더로 바꾸지 않는다.

## 경로와 실행

- 실행 시작 시 제공받은 절대 작업 경로를 고정한다. 현재 디렉터리나 Git 루트를 찾으려고 범위 밖을 탐색하지 않는다. 셸의 작업 디렉터리와 임시 파일·로그·캐시도 전용 영역 내부로 지정한다.
- 파일 열기·검색·해시·복사·생성·편집·삭제·도구 입력·스크립트 실행 모두 이 계약의 적용 대상이다. 상대 경로의 `..`, 절대 경로, 환경변수, 링크를 해석한 실제 대상이 허용 영역 내부인지 확인한다. 접두사가 비슷한 형제 폴더는 허용하지 않는다.
- 심볼릭 링크·정션·reparse point를 따라 영역 밖에 접근하지 않는다. 실경로를 안전하게 확인할 수 없으면 해당 작업을 중단한다. 검색도 전용 영역 또는 `shared/`의 명시한 하위 경로로 한정한다.
- 다른 역할 폴더와 `_workspace/` 바깥은 존재 확인·목록 조회·읽기까지 금지한다. 외부 프로그램이나 하위 프로세스·연결 도구를 통한 우회도 금지한다. 호스트의 실행 바이너리·내부 캐시 관리는 이 문서로 격리됐다고 주장하지 않는다.
- `shared/`의 원본·등록 정보·템플릿은 일반 작업 중 모두 읽기 전용이다. 등록·변경은 사용자 또는 호스트가 수행하며, 유지보수 에이전트는 사용자가 정확한 대상과 변경을 명시한 작업에만 그 예외를 적용한다.

## 기본 검수 게시 권한

- `shared/review-inputs/<handoff_id>/<publisher_role>/`는 검수·인계 사본의 기본 게시 영역이다. 게시자는 `coordinator`, `character-concept-artist`, `monster-concept-artist`, `environment-concept-artist`, `portrait-artist`, `art-director` 중 자신의 역할을 사용한다. 같은 역할의 동시 작업은 담당 세부 폴더를 나눈다. 메인이 다른 역할을 대신해 그 역할 게시 폴더에 쓰지 않는다.
- 게시자는 자기 전용 영역 또는 이미 읽을 수 있는 shared 자료의 이미지·프롬프트·검수·manifest·해시를 자기 게시 영역에 직접 복사할 수 있다. 수신자는 이 사본을 직접 읽거나 자기 전용 영역으로 복사한다. 매 회차 사용자 허용이나 호스트 수동 반입을 요구하지 않는다.
- 게시 완료된 파일은 자기 파일도 덮어쓰지 않고 새 버전 또는 새 handoff_id로 게시한다. 다른 게시자의 파일·manifest·판정을 수정하거나 삭제하지 않는다.
- 실제 파일 복사를 마친 뒤 `handoff.json`을 마지막에 게시한다. 자산·단계·방향·세트 버전과 파일별 SHA-256을 기록하며 수신자는 이 연결과 해시를 확인한다.
- 디렉터는 자신의 검수 사본을 `art-director/` 게시 영역에 작성하거나 메시지로 반환한다. 제작자는 이를 읽어 자기 원본 기록에 반영한다. 다른 역할의 전용 폴더, 공통 디자인·스타일·템플릿, 외부 원본의 접근 권한은 확대하지 않는다.

## 입력·출력과 인계

- 텍스트 브리프·프롬프트·해시·피드백은 에이전트 메시지로 즉시 교환할 수 있다. 호스트가 실제 이미지를 함께 전달하는 컨텍스트 상속·첨부도 사용한다. 수신자가 실제 이미지를 볼 수 있는지 확인하며 경로 문자열만 전달한 것을 이미지 전달로 간주하지 않는다. 이 통신에는 다른 역할 폴더의 직접 접근이 필요하지 않다.
- 입력은 전용 영역의 `inbox/` 또는 `shared/`에 준비된 파일만 사용한다. 외부 경로가 필요하면 사용자 또는 호스트에 사본 반입을 요청한다. 다른 역할의 결과는 해당 제작자의 shared 검수 게시 사본을 사용하며 없으면 담당자에게 게시를 요청한다. 출력은 전용 영역에 새 버전으로 기록한다.
- 인계할 때 자신의 `outbox/<handoff_id>/`에 참조 이미지·결과·프롬프트·검수·manifest 등 필요한 파일과 해시를 모은다. 수신자의 `inbox/`에 직접 쓰지 않는다. 기본 인계는 게시자가 자기 shared 검수 게시 영역에 직접 복사하고 경로·해시를 전달한다. 수신자는 필요하면 shared 사본을 자기 inbox로 복사한다.
- 수신자는 shared 검수 게시 사본 또는 자신의 `inbox/` 사본으로 검수하고 자신의 `reviews/` 또는 `outbox/`에 판단을 남긴다. 다른 에이전트의 manifest나 승인 기록을 직접 수정하지 않는다. 원본 담당자가 되돌아온 검수 사본의 버전·해시를 확인해 자신의 기록에 반영한다.
- 컨텍스트로 이미지와 기록이 온 경우 수신자는 그 실제 자료로 검수하고 메시지로 판정을 반환할 수 있다. 파일 반입이 불필요한 협업을 inbox 사본 대기로 막지 않는다. 컨텍스트에 이미지가 없으면 기본 shared 검수 게시를 사용한다. 외부 원본만 있어 이 방식으로도 제공할 수 없을 때만 사용자·호스트 반입을 요청한다.
- 과거 기록의 외부 경로는 출처 문자열이지 접근 허가가 아니다. 실제 참조는 반입본으로 해석하고 원본 경로·해시와 반입 경로를 구분한다.
- 이미지 도구가 결과를 영역 밖에 저장한다면 그 파일을 직접 열거나 복사하지 않는다. 사용자 또는 호스트의 반입을 요청하고 로컬 저장은 미완료로 표시한다. 출력 경로를 지정할 수 있는 기능이 확인됐을 때만 전용 영역을 지정한다. 경로 제한을 피하려고 임의로 API·CLI로 전환하지 않는다.

실제 OS 수준 격리는 별도 호스트·샌드박스 설정의 책임이다. 이 변경은 파일 접근 행동 지침이며 기술적 차단의 검증 결과가 아니다.
