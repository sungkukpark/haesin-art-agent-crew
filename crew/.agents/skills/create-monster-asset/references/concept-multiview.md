# 괴수 디자인과 네 방향 제작

제작은 `monster-concept-artist`, 검수는 실제 `art-director`다. 함선의 노 수·갑판 층수·돛·선수 화면 방향을 그대로 대입하지 않는다. 입력은 자기 inbox 또는 shared 실제 사본이며 출력은 자기 `monsters/<asset_id>/`다.

## 브리프

| 대상 | 고정할 특징 | 특별 검수 |
| --- | --- | --- |
| whale | 긴 몸통, 머리·등·배의 방향, 한 쌍의 가슴지느러미, 좌우로 펼친 꼬리, 원본 색/표면 특징 | 상어형 수직 꼬리로 변형되지 않는지, 지느러미와 몸통 접합, 수면 위 실루엣 |
| kraken | 큰 머리/몸통과 눈, 방사형 팔, 빨판의 방향, 원본에서 확인한 부속지 수와 접합 | 팔의 중복·누락·융합, 감긴 끝의 부유, 몸통 중심 및 팔 아래 가려진 구조 |
| squid | 길쭉한 외투막, 지느러미, 눈과 팔 군집, 짧은 팔과 긴 촉수의 구분, 원본 색 | 크라켄과의 실루엣 구별, 긴 촉수 끝과 접합, 이동 전방/해부학적 전방 관계 |

- 부속지 수는 실제 원본에서 확인해 적는다. 수중 생물의 일반 지식으로 가려진 개수를 확정하지 않는다. 보이지 않는 면은 추정과 디렉터 합의 사항으로 분리한다.
- `forward`, `up`, 해부학적 좌우, 게임 이동 방향과 해부학적 전방의 관계, 몸통 중심·피벗·수면 기준, 목표 크기를 브리프에 고정한다. 오징어의 외투막 끝이 화면 위라는 이유로 그쪽을 얼굴 방향으로 단정하지 않는다.
- 컨셉의 자세는 몸 전체와 부속지 접합을 확인할 수 있도록 펼친 안정된 자세다. 물·파문·진영 표식·공격 이펙트로 구조를 가리지 않는다. 이것은 정적 디자인 기준이며 리깅용 중립 자세나 정확한 해부학 검증을 보증하지 않는다.
- 디자인 원본은 실루엣·구조·특징, 스타일 원본은 형태 단순화·재질·색·음영을 결정한다. 공통 스타일의 성곽·바퀴·목재 갑판을 괴수 몸에 가져오지 않는다.

## 컨셉

사용 가능한 `imagegen` 스킬을 읽고 내장 이미지 도구로 제작한다. 한 후보는 한 개체 전체의 위에서 내려다본 3/4 정사영풍 이미지 한 장이다. 중립 단색 배경, 일관된 조명, 충분한 여백을 사용하고 사람·함선·풍경·물·문자·콜라주를 추가하지 않는다. 선호 이미지 모델과 실제 보고 모델/seed를 구분하며 미보고 값은 `unknown`이다. 결과 경로가 허용 영역 밖이면 호스트 반입 전까지 로컬 저장을 완료했다고 기록하지 않는다. 임의 API 전환으로 접근 경계를 우회하지 않는다.

실제 프롬프트에는 `subject_reference`, `style_reference`, 수정 시 `previous_result`의 역할·순서를 명시하고 보존 특징·추정·수정 항목을 포함한다. 기존 후보를 새로운 스타일로 취급하지 않는다. 생성 직후 자기 검수하고 실제 이미지·해시·프롬프트·직전 피드백을 디렉터에게 전달한다. `changes_requested`면 필수 수정만 다음 버전에 반영한다. `blocked_missing_evidence`면 같은 후보의 실제 자료부터 보완한다. 기본 최초+수정 2회, 총 3개이며 사용자 선택과 독립 판정은 별도다.

## 멀티뷰

- 승인된 `concept_reference` 한 장의 버전·해시를 모든 호출에 고정한다. Front/Left/Right/Back은 브리프의 개체 로컬 방향을 기준으로 하며 화면 좌우를 개체 좌우로 혼동하지 않는다.
- 정규화 기준에서 Front 카메라는 -Z 쪽에서 +Z를 보고, Back은 +Z에서 -Z를 본다. Left는 -X에서 +X, Right는 +X에서 -X를 본다. +Y 위를 유지하고 각 렌더/이미지의 실제 보이는 면으로 확인한다. 생성 이미지가 이 좌표를 정확히 구현했다고 자동 가정하지 않는다.
- 네 장은 각각 독립 파일이다. 같은 자세·부속지 수/배치·색·재질·축척·수직 기준선·배경·조명을 유지하고, 정면·측면·후면은 수평 정사영풍으로 제작한다. 3/4 시점, 방향별 화면 채움 확대, 단순 좌우 반전은 대체가 아니다.
- 방향별 생성·자기 검수 직후 디렉터 검수하고, 네 장이 모이면 재사용 파일을 포함한 전체 세트도 교차 검수한다. 측면에서 가려진 팔의 연결과 반대편 모습이 승인 컨셉과 모순되지 않는지 확인한다. 자료가 부족하면 같은 후보 자료를 보완하며 새 생성으로 우회하지 않는다.
- 기본 최초 회차 1회+수정 2회, 회차마다 방향당 새 후보 최대 1개/총 12장이다. 한 방향만 고쳐도 수정 회차 하나를 소비한다. 수정 방향은 회차 시작 전에 묶어서 결정하고 동일 방향 재수정은 다음 회차다. 실패한 생성도 사용량에 기록한다.
- 수정은 다음 미사용 세트 버전에 저장하고 재사용 방향의 출처 버전/해시를 유지한다. 동일 필수 결함이 두 번 수정에도 남으면 `repeated_issue`, 그 외 한도 소진은 `iteration_limit_reached`다. 개별 방향 승인만으로 세트를 승인하지 않는다.

## 기록과 인계

자산 루트에 `brief.md`, `manifest.json`; `concept/vNNN/`에 실제 이미지·`prompts.md`·`review.md`; `multiview/vNNN/`에 네 방향 파일·프롬프트·검수·세트 manifest를 둔다. 방향/세트 승인, reviewer ID, 대상 해시, 실제 확인 이미지, 필수/선택 피드백과 반영 결과를 구분한다. 이미지와 해시 연결이 불명확하면 예비 의견일 뿐이다.

게시자는 자기 `outbox/`에서 필요한 파일을 묶어 `shared/review-inputs/<handoff_id>/monster-concept-artist/`에 게시하고 `handoff.json`을 마지막에 작성한다. 기록은 대상 ID·단계·세트/방향·파일별 상대 경로·SHA-256을 포함한다. 수신자의 전용 폴더에 직접 쓰지 않는다. 디렉터는 같은 검수를 재위임하지 않으며, 메인은 승인 세트와 실제 사본이 연결된 후에만 모델 단계로 진행한다.
