# 함선 컨셉부터 모델까지

프로젝트 전용 상위 실행 스킬이다. “이 원본으로 컨셉부터 모델링까지 진행해줘” 또는 “선택한 v001로 멀티뷰부터 모델링까지 진행해줘” 같은 요청에서 단계별 결과를 연결한다. 문서·프롬프트·검수 기록은 한국어로 작성한다.

## 범위와 실행 권한

- 프로젝트 루트 `AGENTS.md`, [작업영역 계약](../../../_workspace/AGENTS.md), [제작·인계 계약](../../../_workspace/shared/agent-workflow.md)을 따른다. 이 스킬은 접근 범위를 늘리지 않는다. 메인은 `_workspace/coordinator/`, 전문 에이전트는 자기 역할 영역에서 작업하며 실제 자료는 자기 shared 검수 게시 사본으로 전달한다.
- 모델링까지 요청한 사용자의 승인은 해당 함선의 참조 업로드·모델 생성·결과 다운로드와 아래 한도 안의 필수 수정에 적용한다. 같은 세션에서 이미 승인한 단계 전환을 다시 묻지 않는다. 사용자 지정 비용·횟수·모델·종료 단계가 우선한다.
- 컨셉만 요청하면 [create-character-concept](../create-character-concept/SKILL.md), 멀티뷰만 요청하면 [create-ship-multiview](../create-ship-multiview/SKILL.md)에서 종료한다. 격리 Godot 임포트 검증을 포함한 정적 패키지가 명시되면 create-unit-assets의 납품 계약으로 연결한다. 실제 프로젝트 반입·씬 교체·게임 적용은 자동 실행 범위가 아니다.
- API 인증은 현재 프로세스 또는 허용 영역에 제공된 설정으로 해결한다. 저장소 밖이나 작업영역 밖의 키 파일·기존 실행기가 읽는 `.env`를 이 스킬만으로 허용하지 않는다. 키 값은 출력하거나 산출물에 기록하지 않는다.

## 시작과 재개

1. 사용자가 지정한 `asset_id`, 원본/스타일 또는 선택한 컨셉/멀티뷰의 실제 파일·버전·해시를 고정한다. 재개할 때 자신의 기록이나 shared 게시 기록에서 생성 중 작업 ID와 완료 단계를 먼저 확인하고 중복 생성하지 않는다.
2. `pipeline.json`을 자신의 자산 폴더에 둔다. 사용자 요청 범위, 선택한 버전, 단계별 입력/출력 해시, 실제 검수자와 판정, 실행 횟수/비용, task ID, 종료 사유를 기록한다. 기존 manifest의 컨셉·모델·게임 적용 이력을 보존한다.
3. 시작부터 실제 `art-director`와 목표·보존할 구조·추정·검수 기준을 협의한다. 제작 전문 에이전트를 쓰면 각 제작 스킬의 협의·검수 회차를 재사용하고 내부 도구마다 중복 위임하지 않는다. 검수자는 재위임하지 않는다.
4. 모델링 도구·인증·허용 출력 경로·예산을 초기에 확인한다. 인증 등의 후속 의존성이 빠져도 독립적으로 할 수 있는 이미지 제작·검수와 제출 자료 준비를 진행한다.

## 단계 연결

### 컨셉

[create-character-concept](../create-character-concept/SKILL.md)를 실행한다. 실제 원본과 공통 스타일을 분리해 한 척의 3/4 시안을 제작하고 실제 디렉터 검수·수정 루프를 따른다. 기존의 사용자가 선택한 승인 시안으로 시작하면 재생성하지 않는다.

디렉터가 `approved_for_next_stage`로 판정하면 결과 버전·해시를 고정해 멀티뷰로 연결한다. 처음부터 끝까지 요청한 실행에서는 디렉터 승인 후보를 진행 기준으로 삼되, 이를 사용자가 직접 선택한 것으로 기록하지 않는다.

### 멀티뷰

[create-ship-multiview](../create-ship-multiview/SKILL.md)를 실행한다. Front·Left·Right·Back 독립 이미지와 실제 방향별/전체 세트 검수가 필요하다. 개별 승인만으로 세트를 승인하지 않는다. 다른 함선의 노 수·비대칭·모델링 수치를 복사하지 않는다.

세트 판정이 `approved_for_next_stage`이면 승인된 네 파일의 해시와 방향을 고정해 모델링에 전달한다. Left는 선수 화면 왼쪽, Right는 선수 화면 오른쪽이다. 실제 기존 사용자 예외 승인이 있으면 그 범위 안에서 적용하되 이전 디렉터 판정도 보존한다.

### 모델 생성·국소 보정·실제 검수

[공통 모델 단계](references/model-stage.md)를 `asset_kind=ship_character`로 수행한다. 승인된 네 방향과 실제 파일 해시를 고정하고, 현재 도구·API 사양과 비용을 확인한 뒤 제출한다. 실제 모델 검사와 6방향 렌더, 필요한 메시·UV 국소 보정과 독립 디렉터 재검수를 포함한다.

이 공통 절차는 괴수 스킬도 사용하지만 함선의 컨셉·멀티뷰를 괴수 제작에 재사용하지 않는다. 총괄 배치에서 호출되면 부모 `batch_id`, 예산·기존 횟수·종료 단계를 그대로 유지한다. 단독 모델 요청은 모델 승인에서 종료하며 명시적인 게임용 패키지 요청만 [정적 납품 계약](../create-unit-assets/references/delivery.md)으로 연결한다. 실제 게임 씬 교체는 실행하지 않는다.

## 반복과 종료

- 컨셉: 해당 스킬의 후보 최대 3개. 멀티뷰: 최초 1회와 수정 2회, 해당 스킬의 총 최대 12장. 중첩 실행으로 예산을 다시 시작하지 않는다.
- 모델: 별도 지정이 없으면 최초 생성 1건과 필수 결함에 대한 수정 최대 2회. 국소 메시·UV 보정도 같은 수정 회차를 소비한다. 전체 모델 단계의 유료 생성/재생성/재텍스처 호출은 합계 최대 3건이며, 사용자 비용 상한이 있으면 그 범위도 지킨다. 최초와 같은 필수 결함이 두 수정에도 남으면 종료한다. 모델·텍스처 하위 단계마다 한도를 따로 늘리지 않는다.
- 자동 단계 전환은 실제 해당 단계 승인 뒤에만 수행한다. `changes_requested`는 한도 안에서 필수 수정 후 같은 기준으로 재검수한다. `blocked_missing_evidence`는 실제 자료 전달부터 해결한다.
- 한도 소진은 `iteration_limit_reached`, 동일 결함 반복은 `repeated_issue`로 실행 상태에 남기며 디렉터 판정을 승인으로 바꾸지 않는다. 필요한 인증이나 입력이 없으면 그 의존성을 구체적으로 보고한다.
- 성공 완료 조건: 고정된 입력에 연결된 실제 모델 파일, 실제 다방향 렌더, 단계별 생성 기록·해시, 최종 모델 버전·해시에 대한 실제 디렉터의 `approved_for_next_stage` 판정. 사용자 직접 선택 상태는 별도로 보존한다. 미해결 결함·근거 부족·반복 실패·예산 소진이면 성공 완료로 기록하지 않고 확보한 산출물과 해당 종료 상태를 전달한다. 최종 응답에는 모델/대표 미리보기 경로, 승인 또는 남은 결함, 실제 비용과 다음부터 사용할 한 문장 호출 예시를 간결히 전달한다.
