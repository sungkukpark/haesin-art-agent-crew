# 공통 정적 모델 생성·보정 계약

호출자가 `asset_kind=ship_character|sea_creature`, 고정 컨셉·승인 멀티뷰·브리프·요청 범위·기존 pipeline을 전달한다. 이 절차는 메인이 자기 `coordinator/ships/<asset_id>/` 또는 `coordinator/monsters/<asset_id>/`에서 수행한다. 외부 원본·다른 역할의 폴더에 접근할 권한을 추가하지 않는다.

## 제출과 복구

1. 허용 영역의 네 방향 실제 파일, 방향별 해시, 최종 세트 승인, 선택 컨셉과의 연결을 확인한다. `changes_requested`인 과거 결과를 폴더명만으로 승인하지 않는다.
2. 현재 허용된 CLI/도구의 도움말·구현과 공식 API 문서에서 모델, 지원 파라미터, 단가, 출력 형식을 확인한다. 과거 모델 ID·면 수·옵션을 최신 사양으로 단정하지 않는다. 새 설치·계정 등록·전역 설정은 부수 작업으로 하지 않는다.
3. 현재 프로세스 또는 허용 설정으로 인증한다. 과거 사용자 예외로 루트 `.env`를 읽는 실행기를 재사용할 수 있는지 확인하고, 이번 권한이 없으면 호출하지 않는다. 키·인증 토큰은 로그·프롬프트·산출물에 기록하지 않는다.
4. 제출 dry-run에 입력 해시·방향, 요청 모델·목표 면 수·텍스처·GLB 출력·현재 견적·누적 지출/예약액을 기록한다. 사용자 예산을 확인하고 다음 호출까지 상한 이내일 때만 제출한다. 계정 잔액으로 한도를 정하지 않는다. 비용 상한을 확인할 수 없으면 호출을 보류한다.
5. API 입력 순서는 `front,left,back,right`다. 명명된 방향 키를 지원하면 키로 전달하고 실제 제출 매핑을 저장한다. 생성 파일명 순서나 렌더 스크립트의 과거 Left/Right 표기를 신뢰하지 않는다. 함선의 과거 입력은 [멀티뷰 방향 계약](../../create-ship-multiview/SKILL.md)의 `local-sides-v2`에 실제 관찰면을 대응시키고 새 매핑의 세트 검수를 받는다. 원본 파일·옛 판정은 보존하며 파일명 교환이나 픽셀 반전으로 승인하지 않는다. 괴수 과거 입력은 [괴수 로컬 방향 계약](../../create-monster-asset/references/concept-multiview.md)과 브리프의 실제 관찰면을 기준으로 같은 매핑·재검수를 수행한다. 함선의 선수 화면 기준을 괴수에 적용하지 않는다.
6. 호출 전에 request 기록을 저장하고 한 번 제출한 뒤 task ID를 즉시 기록한다. 오류·응답 유실·타임아웃은 기존 ID/요청/서비스 상태를 먼저 조회한다. 제출 실패가 확인되지 않으면 새 작업으로 재제출하지 않는다.
7. 실제 다운로드 파일의 형식·크기·SHA-256·내장 텍스처·외부 URI를 검사한다. 서비스 성공과 다운로드 완료를 구분하고 모델 버전·seed·실제 비용이 미보고면 `unknown`으로 남긴다.

## 국소 보정과 독립 검수

- 실제 GLB의 메시·프리미티브·삼각형·재질·텍스처를 검사한다. 목표 수치와 실측, 검증하지 않은 토폴로지/UV 항목을 구분한다.
- 원본 축을 확인한 뒤 +Y 위/-Z 전방으로 맞추고 원본과 별도 버전으로 저장한다. 함선은 -X 좌현/+X 우현이며 괴수는 브리프의 전방·좌우를 따른다. 판옥선의 회전·스케일을 다른 자산에 복사하지 않는다.
- 승인 디자인을 복원하는 노/깃발 수·중복 부품·UV·양면 소실·축 오류 등은 허용 도구로 국소 보정을 우선 검토한다. 부품 연결·재질 배정을 실제로 확인하고 수정 전 모델과 보정 근거·변경 사항을 보존한다. 과거 아타케부네 보정 스크립트의 하드코딩을 다른 자산에 그대로 실행하지 않는다.
- 실루엣·해부 구조·갑판 배치 등을 새로 설계해야 하면 컨셉/멀티뷰로 돌아가 후속 승인을 `stale`로 표시한다. 모델 수정으로 선행 디자인을 몰래 변경하지 않는다.
- 같은 최종 모델에서 Front/Left/Right/Back/3/4/Top의 실제 렌더를 얻는다. 카메라 위치·모델 축·파일명을 함께 기록하고, Front=-Z 관찰/Left=-X 관찰/Right=+X 관찰/Back=+Z 관찰을 확인한다. 함선 Left는 선수 화면 왼쪽, Right는 선수 화면 오른쪽이다.
- 디렉터에게 모델 해시·실제 렌더·고정 컨셉·승인 멀티뷰·검사 결과·수정 이력을 전달한다. 함선은 노·돛·깃발·갑판, 괴수는 몸통·부속지·접합을 중심으로 소실·융합·부유·심한 관통·실루엣 변형을 확인한다.
- 국소 보정·재텍스처·축/재질 변환 이후 기존 승인을 승계하지 않는다. 최종 파일의 해시와 렌더에 대한 실제 디렉터의 `approved_for_next_stage`가 있어야 모델 완료다. 시각 렌더만으로 매니폴드·정확한 UV·연결성·게임 성능을 검증했다고 쓰지 않는다.

## 한도와 인계

기본 모델 최초 1건+필수 수정 2회다. 각 수정 회차에서 국소 보정 또는 유료 재생성/재텍스처를 선택한다. 전체 유료 호출 합계는 최대 3건이며 국소 보정도 수정 회차를 소비한다. 모델 아래 단계마다 한도를 새로 부여하지 않는다. 동일 결함의 두 번 수정 실패는 `repeated_issue`, 그 외 소진은 `iteration_limit_reached`다.

[공통 비용·재개 계약](../../create-unit-assets/references/batch-state.md)의 입력 변경/stale, 승인, 제출 불명/예약액, 상태·횟수·비용 복구 규칙은 단독 함선·괴수에도 적용한다. 단독이면 자산 하나의 기록으로 관리하고, 배치 호출이면 전역 상한도 함께 적용한다. 승인 모델과 6방향 렌더·검사·task/비용 기록을 호출자에게 반환한다. 단독 모델 요청이면 종료하고, 명시적인 패키지 요청만 [정적 납품 계약](../../create-unit-assets/references/delivery.md)으로 이어간다.
