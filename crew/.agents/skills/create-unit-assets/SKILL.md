# 등장 유닛 20종 제작 총괄

전체 또는 지정한 유닛의 제작 상태를 관리하고, 검수된 정적 모델을 이동 가능한 게임용 패키지로 납품한다. 한국어로 제작·검수 기록을 작성한다. 스킬 작성·수정 요청 자체는 실제 이미지 생성이나 유료 모델 호출 요청이 아니다.

## 입력과 접근

- [작업영역 계약](../../../_workspace/AGENTS.md)과 [공통 제작 계약](../../../_workspace/shared/agent-workflow.md)을 따른다. 총괄은 `_workspace/coordinator/`, 제작자는 자기 역할 폴더, 검수 전달은 자기 shared 게시 영역을 사용한다. 원본 경로가 등록돼 있어도 자동 접근 허가는 아니다.
- [20종 등록부 안내](references/catalog.md)를 읽고 `asset_ids`를 고정한다. `all`은 등록된 20종이며, 개장 5단계는 각각 납품하되 하나의 디자인 계열로 비교한다. 제목 배경·아이콘·무기·VFX·적대 괴수 변형은 포함하지 않는다.
- 실행 입력은 `asset_ids`, 허용 영역의 실제 원본/선택 버전, `batch_id`(재개 시 기존 값), 지출 한도와 통화/크레딧 단위다. 종료 단계는 기본 `package`, 명시한 `concept|multiview|model`도 지원한다. 단계 제한은 하위 호출에도 전달한다.
- 디자인은 실제 런타임 PNG, 표현은 등록 공통 스타일을 우선한다. 원본·반입본 해시와 역할을 구분한다. 이번 스킬 설계 때의 외부 PDF/프로젝트 이미지 열람 허용을 향후 실행 권한으로 재사용하지 않는다. 허용 입력이 없으면 해당 유닛만 `blocked_input`으로 기록한다.
- 시작부터 실제 `art-director`와 입력·역할·품질 기준을 협의한다. 함선은 `character-concept-artist`, 괴수는 **`monster-concept-artist`**가 컨셉·멀티뷰를 담당한다. 역할 정의 파일과 실제 호출 가능 상태를 구분하고, 괴수 역할 미로딩 시 `blocked_role`로 기록한다. 함선 아티스트나 메인 제작으로 대체하지 않는다.

## 실행 순서

1. [배치·재개 계약](references/batch-state.md)에 따라 기존 task ID, 승인 버전과 해시, 비용·횟수를 복구한다. 이미 완성된 유닛을 배치 재시작 때문에 다시 생성하지 않는다.
2. 원본·스타일·도구·인증·저장 경로를 확인한다. 과거 Tripo 실행기가 루트 `.env`를 읽는다면 그 실행기를 무조건 사용하지 않는다. 현재 프로세스 인증 또는 허용 설정만 사용하며 키는 출력하지 않는다.
3. 전체 신규 제작의 파일럿은 `player`, `scout`, `kraken` 순서다. 세 종이 요청 종료 단계까지 승인·검증된 뒤 나머지를 등록부 순서로 진행한다. `concept`는 컨셉 승인, `multiview`는 세트 승인, `model`은 모델 승인, `package`는 모델 승인과 패키지 검증이 파일럿 완료 기준이다. 선택 유닛만 요청하면 그 범위를 늘리지 않고 첫 함선/괴수를 해당 유형 파일럿으로 삼는다. 파일럿 이후의 공통 기준을 버전으로 고정한다.
4. 함선은 [create-ship-asset](../create-ship-asset/SKILL.md), 괴수는 [create-monster-asset](../create-monster-asset/SKILL.md)에 위임한다. 단계별 독립 검수는 하위 흐름을 재사용한다. quarter view는 한 유닛의 위에서 내려다본 3/4 컨셉을 뜻한다.
5. 승인 컨셉 → 방향별·세트 승인 멀티뷰 → 모델 생성·필요한 국소 보정 → 실제 다방향 모델 렌더와 독립 승인 순으로 연결한다. 선택된 승인 입력에서 재개하면 선행 이미지를 새로 만들지 않는다.
6. `package` 요청은 [정적 납품 계약](references/delivery.md)을 수행한다. 모델 아트 승인만으로 패키지 완료를 기록하지 않는다. 변환으로 모델 해시가 바뀌면 새 결과를 재검수한다.
7. 전체 비교에서는 실제 승인 결과의 버전·해시를 고정해 개장 단계의 연속성, 함종·진영 식별, 괴수와 함선의 스타일 일관성을 디렉터에게 검수받는다. 아직 없는 결과는 비교 완료로 기록하지 않는다. 앞선 승인 파일을 몰래 교체하지 않는다.

## 품질과 종료

- 거북선 5단계는 기본형 구조를 이어받아 갑판·무장·지휘 구조의 단계별 차이를 보존한다. 원본 차이를 확인하지 않고 장식을 일괄 복제하지 않는다.
- 조총선은 **병사 제외**가 확정 조건이다. 원본의 조총·선체 특징을 살리는 무인 배치를 컨셉에서 검수받으며 현대식 기관총 형태로 바꾸지 않는다.
- 기존 판옥선·고바야부네·세키부네·아타케부네 결과는 비교 자료다. 함종명이나 폴더명만으로 등록 유닛에 대응시키거나 `approved` 폴더를 승인 증거로 사용하지 않는다.
- 기본 범위는 모두 정적이다. 리깅·애니메이션·게임플레이 충돌체·수동 LOD·실제 씬 교체는 포함하지 않는다. 임포터 생성 LOD가 있으면 실제 관찰한 상태만 기록한다.
- 전역 비용 한도와 자산별 횟수 한도를 함께 적용한다. 순차 실행을 기본으로 하여 중복 제출과 예산 경쟁을 피한다. 공통 스타일/파일럿 결함은 후속 공통 생산을 멈추고, 일반 유닛의 개별 실패는 다른 준비된 유닛의 작업을 막지 않는다.
- 최종 응답에는 요청 수/완료 수, 유닛별 패키지 경로·판정·중단 사유, 실제 비용/미확정 비용, 재개 호출을 전달한다. 미완료 유닛이 있으면 전체 성공으로 표현하지 않는다.

## 호출 예시

- `$create-unit-assets 허용 inbox의 원본으로 20종 정적 패키지를 제작해줘. 전체 비용 상한은 600크레딧, batch_id는 fleet-001.`
- `$create-unit-assets player와 kraken만 컨셉까지 제작해줘.`
- `$create-unit-assets batch_id=fleet-001을 기록된 예산과 승인 입력에서 재개해줘. 완료 유닛은 유지해줘.`

예시 금액은 추천 견적이 아니다. 실제 호출 전 현재 요금·견적과 사용자 한도를 확인한다.
