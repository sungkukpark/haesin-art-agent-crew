# 정적 게임용 패키지 납품

기본 완료 범위는 이동 가능한 시각 모델과 격리 Godot 검증이다. 실제 유닛 연결·전투 로직·출시·모바일 성능 인증은 별도다. 모델링만 요청한 단독 스킬에는 이 단계를 자동 추가하지 않는다.

## 패키지 구조와 기록

`coordinator/final-assets/<ships|monsters>/<asset_id>/<vNNN>/`의 새 버전에 다음을 둔다.

- `<asset_id>.glb`: 텍스처가 내장된 최종 정적 모델. 보정 전 생성 원본은 자기 자산 폴더에 별도 보존한다.
- `<asset_id>.tscn`: `Node3D` 아래 최종 GLB를 인스턴스화한 시각 전용 wrapper. GLB는 같은 폴더의 상대 경로로 참조한다. 테스트용 카메라·물·조명·게임 로직은 넣지 않는다.
- `asset.json`: ID·종류, 요청 범위, 출처/라이선스 확인 상태, 단위(m), 실제 크기/AABB, 축·피벗·수면선, wrapper 변환, 자기 파일을 제외한 산출물별 SHA-256, 실측 메시/프리미티브/삼각형/재질/텍스처 정보, 승인 연결, 엔진 검증 상태.
- `previews/`와 `report.md`: 같은 모델 해시의 6방향 렌더, 수면·게임 카메라 조건의 화면, 실제 디렉터 응답, 임포트·재배치 검증과 미검증 항목.

`asset.json` 자체의 최종 해시는 패키지 바깥 pipeline에 기록한다. 자기 파일 해시를 자기 내용에 포함하지 않는다.

리깅·애니메이션·게임플레이 충돌체·수동 LOD는 기본 `not_provided`다. 제공하지 않은 기능을 지원한다고 기록하지 않는다. 출처/권리 정보가 없으면 `unknown`이며 기술적 패키지 완료와 출시 권리 확정을 구분한다.

## 형상·재질 정리

1. 실제 축을 확인하고 `+Y` 위, `-Z` 전방, `-X` 좌측, `+X` 우측으로 정규화한다. 괴수는 브리프의 게임 전방과 해부학적 전방 관계도 기록한다. 앞뒤가 불명확하면 컨셉 브리프로 돌아간다.
2. 미터 단위 목표 크기·수면선·피벗을 브리프와 맞춘다. 허용 자료의 프로젝트 크기 기준이 없으면 그 정보만 요청하고 임의의 다른 함선 스케일을 복사하지 않는다. 기준값이 이미 고정돼 있으면 재질문하지 않는다.
3. 실제 삼각형·프리미티브·재질 수와 텍스처 크기/알파/색공간, 노멀, 외부 URI를 검사한다. 요청 face limit와 실측을 구분한다. 미지원 토폴로지·확장 때문에 확인할 수 없는 수치는 추정 합격으로 처리하지 않는다.
4. 승인 실루엣을 유지하면서 불필요한 중복 메시/재질을 정리한다. 노·돛·촉수 등 얇은 구조와 양면을 렌더로 확인한다. 손실성 단순화는 목표 예산과 시각 비교가 있을 때 수행하며 자동으로 과거 5,000면을 모든 유닛에 적용하지 않는다.
5. 메시·재질·텍스처 변환 후 새로운 해시와 실제 렌더를 다시 검수받는다. 재검수 없는 압축/최적화 사본을 최종 모델로 교체하지 않는다.

## 격리 Godot 검증

- `coordinator/verification/unit-assets/<batch_id>/<asset_id>/<vNNN>/`에 자체 최소 프로젝트를 만든다. 현재 프로젝트에서 허용받아 확인한 엔진 버전·렌더러·카메라 설정을 브리프에 고정한다. 기존 설계의 기준은 Godot 4.7.2·Mobile·1280×720이지만 실행 시 실제 환경을 기록하고 다른 엔진으로 조용히 대체하지 않는다.
- 프로젝트 원본 접근이 허용되지 않은 실행에서는 호스트가 제공한 설정값/사본을 사용한다. 강의 씬·비상업용 자산을 검증 프로젝트에 복제하지 않는다. 단순 수면 평면·자체 조명·카메라만 구성하며 `.godot`·로그·스크린샷도 이 검증 영역에 둔다.
- 허용된 엔진 실행 파일로 해당 격리 프로젝트에 `--headless --editor --import`를 수행한다. 이어서 wrapper 인스턴스 생성, 메시·텍스처 로드, 누락 리소스/파싱 오류, AABB·방향·스케일을 검사한다. 루트 또는 `haesin-3d` 프로젝트의 import 설정을 수정하지 않는다.
- GPU 실행에서 모델 6방향과 수면선·전투 카메라 조건을 확인한다. 재질/텍스처 소실, 거꾸로 된 면, 노·돛·촉수의 부유/심한 관통, 잘린 실루엣, 읽히지 않는 전후 방향을 필수 결함으로 취급한다. 실제 최소 사양·해상도·개체 수·Profiler 증거 없이는 성능 달성을 주장하지 않는다.
- 패키지만 같은 허용 영역의 두 번째 새 프로젝트/다른 하위 경로로 복사하고, 기존 `.godot` 캐시 없이 다시 임포트·인스턴스화한다. `res://` 고정 테스트 경로, 외부 URI, 절대 경로, 테스트 수면/셰이더 의존성이 남으면 실패다. 납품 모델·씬의 해시가 검증 전후 같은지 확인한다.
- 엔진 없음·임포트 실패·GPU 미검증·재배치 실패는 각각 보고한다. 자동 파싱 검사, 시각 검수, 게임 통합, 성능 검증을 서로 대신하지 않는다.

## 완료 판정

최종 GLB 해시에 대한 실제 디렉터 승인, 패키지 의존성 검사, headless 임포트/인스턴스화, GPU 시각 검수, 다른 위치 재임포트를 모두 통과해야 `package.completed`다. 필수 결함·근거 부족·한도 소진은 확보된 산출물과 그대로 전달한다. 기존 모델 승인과 실행 상태를 바꾸어 성공으로 만들지 않는다.
